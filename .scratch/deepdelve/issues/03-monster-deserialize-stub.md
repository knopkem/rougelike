## Agent Brief

**Category:** bug
**Summary:** Loading a save replaces every monster with a dead placeholder at the origin.

**Current behavior:**
`Monster` implements `Deserialize` manually via `IgnoredAny`: any saved monster
comes back as the first `MonsterDef`, empty name, position (0,0), hp 0. Loading
any save corrupts the entire monster list.

**Desired behavior:**
Monsters serialize and deserialize losslessly: def, name, position, hp/max_hp,
and any flags survive a save/load round-trip.

**Key interfaces:**
- `Monster`: replace the manual `IgnoredAny` impl with `#[derive(Deserialize)]`
  (all fields are serde-compatible)
- `MonsterDef`: already derives `Deserialize` — no change needed there
- Keep the existing `Serialize` impl consistent with the derived `Deserialize`

**Acceptance criteria:**
- [ ] A save→load round-trip preserves the full monster list (def, name, pos, hp)
- [ ] No placeholder/`IgnoredAny` code remains in the monster deserialization path
- [ ] `cargo check` passes with no new warnings (the `ignored` variable warning disappears)

**Out of scope:**
- Save file versioning/migration (no existing valid saves matter — the format was corrupting them anyway)
