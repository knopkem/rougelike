## Agent Brief

**Category:** enhancement
**Summary:** The audio engine is never instantiated, playback is a literal no-op, and the mute toggle is unread; wire real playback in per PLAN.

**Current behavior:**
The sfx engine type has zero references outside the audio module. The rodio
playback arm contains a placeholder comment instead of playback. The synth
functions are never called. The `M` mute toggle flips a flag nothing reads.

**Desired behavior:**
The sfx engine is created with the app, game events route through it, and the
existing synth functions produce audible playback through rodio. The mute flag
suppresses all output. The `--no-audio` behavior (issue 22) can then route
through the same engine with output disabled.

**Key interfaces:**
- The sfx engine: instantiated once in the app; its per-event playback function
  called from the event loop where game events are already consumed
- The synth functions: keep their signatures; the engine selects one per game
  event
- The app's mute flag: must gate playback
- Cargo: the rodio dependency is already present

**Acceptance criteria:**
- [ ] With audio enabled, representative events (hit, pickup, level-up,
      stairs) produce sound
- [ ] Pressing `M` mutes/unmutes live
- [ ] No audio output occurs when the engine is constructed in a disabled mode
      (so issue 22's `--no-audio` can reuse it)
- [ ] `cargo check` passes with no new warnings

**Out of scope:**
- Composing new sounds or music
- Volume control beyond mute
- The CLI flag itself (issue 22)
