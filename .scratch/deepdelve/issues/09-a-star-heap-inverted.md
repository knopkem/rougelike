## Agent Brief

**Category:** bug
**Summary:** The pathfinder's open set is a max-heap over f-score, so the worst node is expanded first; paths are suboptimal and search degrades on mazes.

**Current behavior:**
The A* node's `Ord` compares `f` ascending, but `BinaryHeap` pops the maximum,
so the node with the largest f is expanded first. Paths still terminate and
reach the goal but are not optimal.

**Desired behavior:**
The open set pops the node with the smallest f (ties broken by larger g, per
standard A* practice). Paths are shortest-path optimal for the tile cost model.

**Key interfaces:**
- The A* `Node` type's `Ord`/`PartialOrd`: flip the comparison (or invert via
  the negation/min-heap pattern) so minimum-f pops first
- The dead `visited` write and the f-only tie-break may be cleaned up while
  here

**Acceptance criteria:**
- [ ] On a grid where greedy-first expansion takes a detour, the found path
      length equals the optimal path length
- [ ] Existing pathfinding unit tests still pass
- [ ] Add or update a unit test asserting optimality on a case where the
      inverted ordering previously produced a longer path
- [ ] No new compiler warnings

**Out of scope:**
- Replacing A* with a different algorithm
- Tile cost model changes
