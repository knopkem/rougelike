# 08 — take_off_item ignores its slot

## Agent Brief

**Category:** bug
**Summary:** Taking off equipment always removes armor, regardless of the requested slot; rings can never be removed.

**Current behavior:**
`take_off_item` takes a slot argument it ignores (`_slot`) and unconditionally
removes the armor. The core `Action::TakeOff` route passes the same inventory
index used by Drop/Wear/Wield, so taking off a ring removes armor instead.

**Desired behavior:**
`take_off_item` inspects the item at the given slot and removes it from the
correct location: armor for an armor item, the matching ring slot for a ring,
and a clear message for anything that can't be taken off.

**Key interfaces:**
- `Game::take_off_item(slot)`: branch on the item's kind at that slot
- The `Action::TakeOff` route in `player_turn`: semantics must match — clarify
  whether it carries an inventory index or an equipment slot, and make the
  route and the function agree
- Ring equipment model on the player: ring slots must be identifiable by the
  ring's id

**Acceptance criteria:**
- [ ] Taking off worn armor removes the armor
- [ ] Taking off a worn ring removes that ring, not the armor
- [ ] Taking off a non-equipable slot state logs a sensible message
- [ ] The action route and the function agree on what the slot argument means

**Out of scope:**
- Re-equipping / swapping logic (Wear/Wield paths)
