## Agent Brief

**Category:** bug
**Summary:** Every death or victory writes two hiscore entries instead of one.

**Current behavior:**
`Game`'s death and victory checks each call `hiscore::record`, and the main loop
calls `hiscore::record(game)` again after `do_turn` returns. `hiscore::record`
pushes unconditionally with no dedup, so each run end produces two entries.

**Desired behavior:**
Exactly one hiscore entry is written when a run ends (death or victory),
regardless of how the run ended.

**Key interfaces:**
- `hiscore::record`: keep as the single writer; do not add dedup as the fix —
  remove the redundant call sites instead
- `Game::check_death` / `Game::check_victory`: one of these vs the main loop is
  the sole place `record` is invoked
- The main loop's post-`do_turn` handling: must still detect that the run ended
  to break out of the loop

**Acceptance criteria:**
- [ ] A run ended by death produces exactly one new hiscore entry
- [ ] A run ended by victory produces exactly one new hiscore entry
- [ ] An in-progress run produces no hiscore entries
- [ ] `cargo check` passes with no new warnings

**Out of scope:**
- Changing the hiscore file format or ordering
- Score computation logic
