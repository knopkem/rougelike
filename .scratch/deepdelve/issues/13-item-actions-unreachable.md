## Agent Brief

**Category:** enhancement
**Summary:** The core implements every item action, but no key produces any of them — the player can pick up items but never use, equip, drop, or read them.

**Current behavior:**
The UI play-state key handler binds only movement, wait, stairs, pickup,
inventory panel, and quit. The core's item actions (use, drop, wield, wear,
take-off, ring on/off, eat, quaff, read, identify, fire wand, plus the
otherwise-unrouted talk/buy/sell actions) are all unreachable from input.
The inventory panel is display-only.

**Desired behavior:**
Keyboard bindings plus an inventory item picker let the player perform every
core item action. The inventory panel remains display-only; selection happens
in the picker.

**Key interfaces:**
- The UI key handler for the play state: new bindings. NOTE: the original
  suggestion "q=quaff" is taken — `q` already quits; choose free keys and
  document the full binding table in the help screen
- A new inventory-picker UI surface (list of inventory slots, arrow/letter
  selection, cancel), reusing existing panel rendering patterns
- The core's existing `Action` variants: no core changes expected; the UI maps
  key + picker result → action

**Acceptance criteria:**
- [ ] Each core item action has a reachable key path (documented in the help
      screen), including at least: quaff, eat, drop, wield, wear, take-off,
      ring on/off, read, identify
- [ ] The item picker lists inventory slots and maps a selection to the
      correct action with that slot
- [ ] Canceled selection does nothing
- [ ] No existing key binding changes meaning (quit stays `q`)
- [ ] The help screen lists all new bindings

**Out of scope:**
- Wand target firing (issue 14 builds on the picker)
- Shop buy/sell actions (issue 16)
- New item actions in the core
