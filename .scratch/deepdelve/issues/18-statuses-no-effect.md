## Agent Brief

**Category:** enhancement
**Summary:** Status effects tick down but change no behavior; worse, nothing ever sets them. Implement the planned status mechanics per PLAN.

**Current behavior:**
Confusion/paralysis/invisibility counters decrement with zero mechanical
effect (no movement lockout, no AI reaction, no invisibility flag). Hunger is
a flat 1 HP/turn at zero, not the planned multi-stage starving ladder. No
sickness/petrification/burn/slow exist. Additionally: no code path ever sets
any status — the only writes are cures setting poison to zero.

**Desired behavior:**
Per PLAN: confusion deranges player input; paralysis blocks player movement;
invisibility hides the player from monster sight; poison/disease tick damage;
hunger is a multi-stage ladder (weak → starving → dying) with escalating HP
loss; the missing status kinds (sickness, petrification, burn, slow) exist
with their planned effects. Statuses are actually applied by the sources that
should apply them (potion/scroll side effects, traps, monsters with abilities
once those land).

**Key interfaces:**
- The player statuses struct: fields already exist for several kinds; add the
  missing ones
- The per-turn status tick: apply the mechanical effects
- The player turn handler: respect paralysis/confusion before acting
- Monster AI sight check: consult the invisibility flag (coordination point
  with issue 19 — the AI's sight roll is being replaced there)

**Acceptance criteria:**
- [ ] Paralyzed player cannot move or act on their turn (message explains why)
- [ ] Confused player's movement is deranged per the planned rule
- [ ] Invisible player is not targeted by monsters using sight
- [ ] Poison ticks damage per plan; curing it stops the ticks
- [ ] Hunger at zero progresses through the planned stages with escalating
      effects
- [ ] At least one live source sets each implemented status

**Out of scope:**
- New status kinds beyond the planned set
- Status UI beyond the existing status panel
