## Agent Brief

**Category:** enhancement
**Summary:** The targeting state exists in the UI but is never entered, so wands can never be fired.

**Current behavior:**
The UI's targeting state is initialized `None` and never set; the targeting
key handler is dead code. No key exists to pick a wand, so `Action::FireWand`
can never fire.

**Desired behavior:**
A wand key opens the item picker (from issue 13); selecting a wand enters the
existing targeting flow (arrow keys + Enter to fire at a target), producing
`Action::FireWand`.

**Key interfaces:**
- The UI key handler: new wand key → item picker filtered to wands
- The existing targeting state and handler: wire the entry point; the
  arrow+Enter flow already exists
- The core's `Action::FireWand` route: no change expected

**Acceptance criteria:**
- [ ] Pressing the wand key with a wand in inventory enters targeting with
      that wand
- [ ] Arrow keys move the target cursor; Enter fires the wand at the target;
      Esc cancels
- [ ] Pressing the wand key with no wand in inventory does nothing sensible
      (message or no-op)
- [ ] Firing a wand dispatches the core action and the wand is consumed per
      the core's existing behavior

**Out of scope:**
- New wand kinds or wand mechanics in the core
- Targeting UI beyond the existing arrow+Enter flow
