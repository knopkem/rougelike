## Agent Brief

**Category:** bug
**Summary:** Reading a scroll does nothing and most potions are inert; the real implementations in the magic module are dead code.

**Current behavior:**
`Game::apply_scroll` is a log-only line with zero scroll effects (no identify,
teleport, map, enchant, or remove-curse). `Game::apply_potion` only handles
Healing and CurePoison; everything else falls through to a log-only default.
The magic module already contains fuller implementations (`apply_potion_full`,
`apply_scroll_full`) that nothing calls, and its teleport arm emits an event
but never moves the player.

**Desired behavior:**
Quaffing and reading items route through the magic module's implementations so
all planned potion and scroll kinds have their effects; teleport actually
relocates the player. The dead duplicate paths are removed.

**Key interfaces:**
- `Game::apply_potion` / `Game::apply_scroll`: delegate to the magic module
- The magic module's full potion/scroll implementations: fix the teleport arm
  to actually change the player's position (respecting walkability), then wire
  them in
- Item identification: a working `identify_item` already exists in the core;
  the identify scroll should use it

**Acceptance criteria:**
- [ ] Each implemented scroll kind (identify, teleport, map, enchant,
      remove-curse per PLAN) produces its effect when read
- [ ] Teleport moves the player to a valid, walkable location
- [ ] Each implemented potion kind has its effect when quaffed
- [ ] No dead duplicate implementation remains uncalled

**Out of scope:**
- New scroll/potion kinds beyond the planned set
- Wand effects (separate item path)
