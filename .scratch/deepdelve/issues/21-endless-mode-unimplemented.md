## Agent Brief

**Category:** enhancement
**Summary:** After taking the amulet the run hard-ends; the planned optional endless descent is unreachable, though its scaling plumbing already exists.

**Current behavior:**
The `Game::endless` flag is initialized false and never set. Descending caps
at the max depth constant, and victory ends the run at the amulet. The
depth-beyond-max monster scaling branch in spawning exists but is dead.

**Desired behavior:**
When the player picks up the amulet, they may continue descending: generation
keeps producing levels beyond the old cap using the existing depth-scaling
spawn branch, and the old victory path (run ends) remains the alternative
behavior per PLAN (endless is optional — confirm the trigger: prompt on
pickup, or a flag).

**Key interfaces:**
- `Game::endless`: set at the amulet pickup decision point
- The descend handler: lift the max-depth cap while endless is active
- The victory check: only fires when the player chose to end the run
- Spawn scaling branch: already handles depths beyond the cap; wire it live

**Acceptance criteria:**
- [ ] Picking up the amulet offers the endless choice (or the trigger decided
      during implementation review of PLAN); declining ends the run as today
- [ ] Choosing endless allows descending past the old max depth
- [ ] Monsters beyond the cap use the existing scaling branch
- [ ] The run still ends normally if the player declines endless

**Out of scope:**
- New content tiers beyond the existing scaling branch
- Endless-specific UI (beyond the prompt)
