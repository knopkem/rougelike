# 04 — RNG stream resets on save/load

## Agent Brief

**Category:** bug
**Summary:** After loading a save, the RNG restarts from the seed, replaying the same random prefix as the start of the run.

**Current behavior:**
The game RNG serializes only the seed and reconstructs via `Rng::new(seed)` on
load, which re-creates the generator from the seed. Post-load random events
replay the same prefix as run start, so save/resume is not faithful.

**Desired behavior:**
Persist the actual generator state so the random stream continues exactly where
it left off after a save/load. The seed remains available as a plain field for
reproducibility metadata.

**Key interfaces:**
- The RNG wrapper's `Serialize`/`Deserialize`: persist the inner `ChaCha8Rng`
  state instead of the seed
- `Cargo.toml`: enable the `serde` feature of `rand_chacha`
- `Rng::new(seed)` construction path stays for new games

**Acceptance criteria:**
- [ ] After save→load, the next N random draws match the draws that would have
      followed without the save (no replayed prefix)
- [ ] A new game still constructs its RNG from a given seed
- [ ] `cargo check` passes

**Out of scope:**
- Deterministic replay tooling (see issue 22 for `--seed` flag work)
