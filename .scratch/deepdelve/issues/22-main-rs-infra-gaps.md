## Agent Brief

**Category:** enhancement
**Summary:** No CLI flags, no panic/terminal-restore guard, and the seed comes from the wall clock — the binary's required infrastructure per PLAN is missing.

**Current behavior:**
The binary parses no arguments (`--seed`, `--headless`, `--no-audio` are all
required by PLAN). There is no panic hook and no Drop-based terminal restore:
a panic leaves the terminal in raw mode on the alternate screen. The seed is
derived from `SystemTime`, so runs aren't reproducible from outside.

**Desired behavior:**
`--seed <u64>` sets the run seed; `--headless` runs the game loop without the
curses UI (the natural home for the simulation/integration tests in issue 23);
`--no-audio` disables the audio engine (see issue 17 for the seam). A panic
hook and a guard that runs on all exit paths restore the terminal. The default
(no flags) behavior is unchanged except the seed is logged so runs are
reproducible.

**Key interfaces:**
- Argument parsing in the binary entry point
- A terminal-restore guard (Drop-based or equivalent) wrapping the UI loop,
  plus a panic hook that logs and restores
- The game loop: a headless driver that feeds the same `do_turn`/event path
  without curses
- Seed: explicit flag value, else generated; always reported (log line /
  hiscore) so any run is reproducible

**Acceptance criteria:**
- [ ] `--seed 42` produces a deterministic run (same map/monsters for the
      same seed, modulo the RNG fix in issue 04)
- [ ] `--headless` runs and exits cleanly without a terminal
- [ ] `--no-audio` starts with audio disabled
- [ ] A panic mid-run restores the terminal (test: kill -ABRT or a deliberate
      panic in a debug build leaves the shell usable)
- [ ] Default invocation behaves as before for an interactive session

**Out of scope:**
- Test-suite contents (issue 23)
- Audio implementation (issue 17)
