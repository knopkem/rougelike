# 02 — Dead autosave resurrects a dead game

> *This was generated by AI during triage.*

Status: done
Category: bug
Source: ISSUES.md #2 (verified 2026-08-20: CONFIRMED)

## Agent Brief

**Category:** bug
**Summary:** Autosave runs after the death/victory turn and re-writes a save the game just deleted, so a dead game can be loaded.

**Current behavior:**
The main loop unconditionally calls `save::autosave(game)` after every turn,
including the turn on which the player dies or wins. The death/victory checks
delete the autosave, then main re-writes it with `alive = false` / `won = true`.
The title screen shows "Continue" whenever an autosave file exists, offering an
unplayable dead game.

**Desired behavior:**
Autosave only happens for a live, ongoing run. After death or victory no
autosave file exists and the title screen offers no "Continue" entry.

**Key interfaces:**
- `save::autosave`: guard the write so it is a no-op (or is not called) when the
  game is dead or won
- The main loop's per-turn save step
- Title-screen "Continue" visibility: must reflect only loadable, playable
  autosaves

**Acceptance criteria:**
- [x] After the death turn, no autosave file remains on disk
- [x] After the victory turn, no autosave file remains on disk
- [x] A mid-run autosave still writes normally
- [x] Title screen hides "Continue" when no valid autosave exists

**Out of scope:**
- The hiscore path (see issue 01)
- Save file format changes

## Comments

> *This was generated by AI during triage.*

- Verified 2026-08-20: `autosave` has no alive/won guard; victory is affected in
  addition to death (covered by the same `game.alive && !game.won` guard).
- Implemented: `save::autosave` is a no-op when `!game.alive || game.won`
  (covers the main loop's per-turn save and the stairs-down autosave);
  `save::load_autosave` rejects dead/won saves so the title screen's
  "Continue" only offers playable autosaves (also protects against stale
  files from older builds). Tests in `save.rs` at the autosave/load seam
  with an isolated XDG_DATA_HOME; shared `with_isolated_data_dir` helper
  moved to `tests_harness`.
